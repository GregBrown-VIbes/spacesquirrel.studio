Writing a tutorial

For add-on makers, riggers and character sellers. Kneady tutorials are data: a folder with a tutorial.json, its clips and a practice scene.

A Kneady tutorial plays in the 3D view: a panel down the view's left side, where the toolbar is, with short vertical clips of the gesture - or still images - at the top, the step's text under them, and Back, Reset and Next at the bottom. Kneady's own sidebar is lit live where a step points at it, so a tutorial doesn't go stale when the panel changes. A step can watch for what it asks and tick itself off.

With Help set to Learn, where Kneady starts, the top of the Kneady tab has Start a Tutorial, a menu of every tutorial, and beside it a pencil: Edit mode, where tutorials are written. They are in the Tutorials panel, which folds away by its header like any of Blender's panels - in one window and not another, so a window you record the Kneady tab in can have it folded while you write in the other.

Writing one in the Kneady tab

  1. Set Help to Learn and press the pencil beside Start a Tutorial.
  2. + makes a tutorial; the dropdown picks one to change; the bin deletes the one picked (to the Recycle Bin on Windows). The folder icon chooses where tutorials are saved - your folder (below).
  3. Tutorial: its title, the summary its tooltip shows, its order in the menu (tutorials are numbered in it, from 1 - or from 0 when the first has order 0, one that comes before the rest, as Kneady's own Learn, Inform and Quiet), its practice scene (the file icon makes the file that is open the practice scene: a copy saved into the tutorial's folder), where its media are hosted, and its Playlist, to watch it on a phone (see "On a phone").
  4. Shared Media: clips and images for every step without its own.
  5. Steps: the list, with + and - and the arrows. For the one selected:
    • Text: its paragraphs. The pencil beside one opens it in a wide box.
    • Media: the shared set, its own, or none. Each clip or image is Local (it ships in the tutorial's folder) or Hosted (downloaded when played - see below). The folder icon beside its file chooses the clip or image and copies it to where it belongs; the line under it says where it is and whether it will ship. Hold at End keeps it on its last frame once it has played. Trim is the frames that play (see "Trimming"). Watch Link is where to watch it online - a YouTube Short - for when it can't be shown here.
    • Highlight: fields to light in Kneady's panels - the Tutorials panel's editor too. Hover a field, press Ctrl+Shift+Alt+C (Copy Full Data Path), then the paste icon.
    • Done When: what ticks the step off. Done by the person, the step moves on to the next by itself a moment later; Next works too. The eyedropper takes a property's value as it is now.
    • Start: what the step sets up. Use Current takes the mode, the selection, the view or the sidebar's tab from the scene as it is.
  6. What is wrong is listed under Save as you type. Save writes the tutorial; Try saves it and plays it from the step selected, in the file that is open - its starts change this file's scene, which Ctrl+Z puts back. Tried while a tutorial plays in its practice scene (as in Write a Tutorial), the one tried takes its place and keeps its Return to My File. The panel shows your edits as you make them, but Start a Tutorial plays what is saved: started with edits not saved yet, it asks
    • Save and Play, or Play Saved Version.

Examples

A step that asks for something - haul a Kneady button, click one, hover a region, press a panel's button, change a field, select an object - says so under Done When: an Action (a Kneady button hauled or clicked, on which region and object, or any other operator by its name, as object.mode_set), Hovered (a region), a Property that becomes a value or changes, the Mode, the Active Object or what is Selected. Its Start sets the scene up so it can be done; Highlight lights the field it is about.

The panel shows it as you write. While Edit mode is on, the tutorial's panel over the view shows the tutorial being edited, unsaved changes and all, at the step selected in the list - its header says Editing. Type a paragraph, add a clip, change what a step lights, and the panel and Kneady's own panels show it a moment later. Selecting a step in the list shows it in the panel; Back and Next in the panel select it in the list. Going from step to step there sets nothing up, so editing never moves your scene; Reset sets the step up on purpose, to try its start. A local clip or image shows from this computer, "not recorded yet" until it's there; a hosted one plays from its copy on this computer, or downloads, so what you put online can be checked. The eye beside Save hides it, as does its x; Try plays the tutorial for real, and the preview comes back when that ends.

Your folder. Tutorials are saved in your tutorials folder: in a copy of Kneady's repository, its own tutorials/; installed, Kneady's folder in Blender's user files, which an update leaves alone. The folder icon chooses another. Changing one of Kneady's own tutorials saves a copy into your folder, practice scene and media with it, and the copy is the one listed.

The rest of this guide is the file the editor writes, for reading it or writing one by hand.

A tutorial is a folder

tutorials/quick_start/
    tutorial.json      the steps
    practice.blend     the scene it runs in (optional)
    01_select.mp4      its local clips and images, which ship with it
    where.png

dev/media/quick_start/
    02_region.mp4      copies of its hosted ones, to upload (see below)

A tutorial is data only. Nothing in it runs as Python: what a step checks or sets is a property named by a path, which Blender looks up the way a driver does. A clip or image is named by its file's name alone, never a path, so a tutorial can only show what is in its own folder.

Where tutorials come from

Start a Tutorial lists them under where each comes from:

  • Kneady: Kneady's own tutorials/ folder.
  • An add-on: any enabled add-on with a kneady_tutorials/ folder in its own folder, listed under the add-on's name. The add-on calls nothing of Kneady's, so any add-on can ship tutorials this way.
  • In This File: tutorials attached to an item in the open file (below).
  • Yours: the folder you write tutorials in.

Folders whose names start with _ or . are never tutorials: a tutorials folder's _scenes/ holds practice scenes several tutorials share. Two tutorials with the same folder name: the later one in this list is shown, so a copy of Kneady's own that you've changed takes its place.

Attached to an item, in a file

A rigger can give a rig its own tutorials, which travel in its file:

  1. Open the rig's file and write the tutorial as any other.
  2. Select the rig, and in the editor press Attach to Rig (Attach to Item, named for the active object).
  3. Save the file.

The tutorial, its clips and its images are stored on the object. It goes wherever the object goes: opened in its own file, or appended or linked into another, as an animator links a rig into a shot. Five copies of the rig in a shot list it once. It runs in the file it is in, never a practice scene, so its starts should change as little as possible.

  • Where it shows: under In This File in Start a Tutorial, and at Help's Inform level too, as Tutorials in This File at the top of the Kneady tab. Quiet shows none.
  • Editing: pick it in the editor and edit as usual. Save writes it back into its object: save the file to keep it. Ctrl+Z undoes it. A linked rig's tutorials are changed in the rig's own file.
  • Save to Folder copies it out to your tutorials folder as a tutorial of its own. Delete takes it off the object.
  • Size: every clip adds to the file. To keep a file small, host the clips online (see Local or hosted); a hosted clip stays out of the file.
  • Safe: it is data, as every tutorial is. Opening someone else's file that carries tutorials runs nothing.

Clips and images

Kneady's own tutorials have their clips made by script, not recorded by hand: dev/clips/ in Kneady's repository plays each step in a Recording Window with simulated input, draws the cursor on and encodes the MP4. When the interface changes, the clips are made again to match. Its README says how.

  • Vertical, 9:16 (4:5 works too; the panel fits whatever shape it gets).
  • 720 x 1280 is ideal; 540 x 960 is the least that stays sharp. The panel shows a clip 234 x 416 pixels times Blender's interface scale (the Resolution Scale preference times the screen's own, 2 on a Retina or 4K screen): 293 wide at 1.25, 468 at 2, so 720 is sharp up to 3. Each frame is decoded in Blender as it plays, so a bigger clip costs more for no gain. 1080 x 1920 only if the same clips also go to Shorts or Reels.
  • Shown small, so record close. A 720-wide clip of the screen shows at about 40% of its size at 1.25, interface text and all. Zoom the view in until the gesture fills the frame; for a clip of a panel, set Resolution Scale to 2 while recording, then back.
  • Clips: MP4 (H.264), a few seconds long. There is no sound. (.mov, .webm, .mkv and .avi play too.)
  • Any frame rate, held constant. Each clip plays at its own rate - 15, 24, 30 - mixed freely in one tutorial. The rate must not vary within a clip: OBS records a constant one; some quick screen recorders do not. 15 is enough for interface work, and halves what Blender decodes as it plays; a fast drag looks a little stepped.
  • Smaller files come from the bitrate, not the frame rate. Recorded at a set bitrate (OBS's CBR), a 15 fps clip is the size of a 30 fps one. Record at a set quality instead - OBS's Recording Quality "High Quality, Medium File Size", or Rate Control CRF / CQP - and a still screen costs almost nothing.
  • Images: PNG or JPEG, for a moment that needs no motion - where a setting is, what a finished pose looks like.
  • One gesture per clip. A step can have several: the gesture in the viewport, then where to find something in Blender's own interface.
  • The same clips can go to YouTube Shorts, Reels or TikTok as they are.

Recording a clip. Any screen recorder will do, at the size above. With OBS: make Blender's window - or a window of its own, View > Area > Duplicate Area into New Window - its inside 720 x 1280, add a Window Capture source for it with Client Area on (the inside only) and Capture Cursor on, and set Settings > Video, Base and Output Resolution, to 720x1280, so nothing is scaled. Record as MPEG-4 or Hybrid MP4 (Settings > Output > Recording Format), then choose the file with the folder icon beside the clip's File.

Trimming. A clip's Trim is the frames that play: Trim Start and End in its settings, counted from 1 - 0 is the clip's own start or end. Under them, what the trim keeps ("Keeps 2.0 of 10.0 s"). The panel plays the kept frames round, or holds the last. A trim is only marks: the file keeps every frame. For a file of just the kept frames - smaller, for posting - cut it in any video editor.

Pro Kneady Pro adds tools for this: a window sized for recording, recording a clip with OBS from the panel straight into its place, a trim bar under the clip to drag, Apply Trim, and Record What You Do, which turns what you do into a step's Done When, Start and Highlight. What they make is ordinary tutorial data, played here as it is.

A missing file shows "Clip not recorded yet" or "Image not added yet" and its name in its place, so a tutorial can be written and tried before its media exist.

Local or hosted

Each clip or image is one or the other.

  • Local (the default): its file is in the tutorial's own folder and ships with it. It works offline and without Blender's Allow Online Access - so a first tutorial should be all local. Quick Start is.
  • Hosted ("hosted": true): downloaded from the tutorial's media_url followed by the file's name, or from the item's own url, in the background when the tutorial starts, and kept in Kneady's folder in Blender's user files, so it comes once. Hosted keeps a tutorial small, for long or many clips.

Downloading needs Allow Online Access on (Preferences > System), as Blender asks of every extension. It is off in a new Blender, so the panel says so in the clip's place, and a click there opens Preferences. Only https:// addresses are used, and certificates are checked against both the computer's own and Blender's, so an office network that checks secure traffic with its own certificate works too.

A hosted item's copy on your computer - to play while you write, and to upload - is kept apart, where it never ships: in Kneady's repository, dev/media/<tutorial>/; in any other tutorials folder, its .hosted/<tutorial>/. The editor's folder icon puts it there.

Watch Link. Any clip can have a watch address, such as its YouTube Short. Whenever it can't be shown here - not recorded, Online Access off, a download that failed, a Blender that can't play video - a Watch on YouTube button in its place opens it in the person's browser.

To publish hosted ones:

  1. Record into dev/media/<tutorial>/ and try the tutorial.
  2. Run python dev/publish_media.py <tutorial>. It writes each file's sha256 fingerprint into tutorial.json - Kneady refuses a download that isn't that file - and lists each file with the address it has to be found at.
  3. Upload them there - a GitHub release of a public repository works: create the release, then attach the files to it.
  4. To replace a clip, give the new recording a new file name (01_turn_on_2.mp4), point the step at it, run the script and upload it. It reaches people with the next Kneady release, which carries the new tutorial.json. Leave the old file online: a Kneady already installed still asks for it, and refuses a different file under its old name.

On a phone

A tutorial's Playlist is where the whole tutorial can be watched on a phone - a YouTube playlist of its clips, in order. The panel's title row then has a phone button, which shows the link as a QR code in place of the clip and the text. A phone's camera opens it, and the person swipes to the clip they want; a click on the code goes back. The clip waits while the code shows.

  • Make the playlist Public or Unlisted. A Private one opens for no one but you.
  • One link for the whole tutorial, not one per clip: a person scans once.
  • Only an https:// address is taken.

tutorial.json

{
  "format": 1,
  "title": "Quick Start",
  "summary": "One line on what it teaches.",
  "order": 1,
  "practice": "practice.blend",
  "playlist": "https://www.youtube.com/playlist?list=...",
  "media": [
    {"file": "overview.mp4", "label": "In the viewport"}
  ],
  "steps": [
    {
      "title": "Turn Kneady on",
      "text": ["A paragraph.", "Another, the clip's: Properties > Modifiers > Kneady."],
      "media": [
        {"file": "01_turn_on.mp4", "label": "In the 3D view's header", "paragraph": 1, "hold": true,
         "trim": [12, 96],
         "recorded": {"blender": "5.2", "kneady": "1.0.0"},
         "show_me": {"sidebar": "Kneady"}},
        {"file": "where.png", "label": "The Kneady tab", "paragraph": 1, "seconds": 4}
      ],
      "highlight": ["scene.kneady_on"],
      "done_when": [{"path": "scene.kneady_on", "is": true}],
      "start": {"mode": "OBJECT", "select": [], "active": "Arm",
                "set": [{"path": "scene.kneady_on", "value": false}],
                "view": {"location": [0, 0, 1], "rotation": [1, 0, 0, 0], "distance": 6},
                "sidebar": "Kneady"}
    }
  ]
}

At the top, playlist is where the whole tutorial is watched on a phone, shown as a QR code (see "On a phone").

Everything in a step is optional except text.

  • text: the step's paragraphs. Keep them short; the panel is narrow. Write a path through Blender's interface as a breadcrumb: Properties > Modifiers > Kneady > Speed.

  • media: the step's clips and images, each with its file, a label saying where to look ("In the viewport", "Properties > Modifiers"), and the paragraph it goes with, counted from 0. While it shows, its paragraph is lit and scrolled into view. A step's media play one after another and start over; an image stays up for its seconds (4 if it doesn't say) before the next. A clip alone in its step plays again and again.

    • hold: true to stay on its last frame once it has played - an image, on it - rather than playing again or going on to the next. A clip that ends on the result is one to hold. The arrows and dots still go on.
    • trim: [first, last], the frames that play, counted from 1 - last 0 for the clip's end. The clip's Trim in the editor (see "Trimming").
    • The person's Pause and Loop, in the row under the clip, are for the item showing only: Pause pauses it (Play on one held at its end starts it over), and Loop plays it again and again, whatever it says. The next item starts as it says.
    • A step's own, or the shared set. A step with media shows its own; "media": [] shows none; a step without the key shows the tutorial's shared set, media at the top of the file. Going from one step that shares the set to another keeps its place, so one clip can play on under several pages of text. A shared item lights its paragraph on whichever step has that paragraph.
    • hosted: true for one downloaded rather than shipped. url: where it is hosted, when it isn't at the tutorial's media_url (an item with a url is hosted). sha256: its fingerprint, written by publish_media.py.
    • watch: where to watch it online, for a Watch button when it can't be shown here.
    • recorded: the Blender and Kneady versions it was made in (the editor's refresh icon beside them stamps this Blender's and Kneady's). The editor counts the clips and images made in other versions, so the ones that may show an old interface are found after an update.
    • show_me: a Show Me button under the clip, opening the place it shows: {"sidebar": "Kneady"} for a sidebar tab, or {"properties": "MODIFIER", "object": "Arm", "modifier": "GeometryNodes"} for a Properties editor's tab, with an object made active and a modifier opened.

  • highlight: properties in Kneady's own panels to light up.

  • done_when: conditions that all have to hold for the step to tick itself off. Each is a path and one test, or a state on its own:

    Condition Holds when
    {"path": P, "is": V} the value is V (numbers to a hair; lists for vectors)
    {"path": P, "is_not": V} it isn't
    {"path": P, "at_least": N}, "at_most" a number past N
    {"path": P, "changed": true} it differs from when the step began
    {"path": P, "count_at_least": N} a collection has N or more
    {"operator": "kneady.drag", "with": {"target": "Arm", "region": 1, "button": 0}, "moved": true} that Kneady button was hauled since the step began ("moved": false: clicked; leave it out for either). Only what with names is checked
    {"operator": "object.mode_set", "with": {"mode": "POSE"}} any other operator run since the step began - from a panel's button or a key - that Blender keeps in its history
    {"hovered": "Forearm", "object": "Arm"} that region was hovered since the step began (object optional)
    {"mode": "POSE"} Blender is in that mode
    {"active": "Arm"} that object is active
    {"selected": ["Arm", "ArmRig"]} those objects are selected

    A step with no conditions has nothing to tick; Next is always there.

  • start: what the step sets up, every time it's entered and when Reset is pressed, as one undo step. mode, select (object names, the rest deselected), active, set (paths and values), view (the 3D view's location, rotation as w, x, y, z, distance and perspective) and sidebar (a tab to open).

Paths start at scene, object (the active object), objects["Name"], window_manager or space (the tutorial's 3D view), and go on the way Blender's data paths do: objects["ArmRig"].pose.bones["Lower"].rotation_quaternion. The editor's paste icon turns one copied with Copy Full Data Path into this form.

The practice scene

A tutorial with practice opens a copy of that file from the temporary folder. Blender asks the person to save their own file first, through its usual prompt, and Return to My File opens their file again at the end. Nothing they do in the practice scene is kept.

Opening a file clears Blender's undo history: their work is saved, but not their undo steps. A tutorial without a practice scene runs in whatever file is open, so its starts should change as little as possible.

  • The editor's Use This File makes the file that is open the practice scene. For Kneady's own tutorials, make it with a script instead, so it can be made again. The shared scenes in tutorials/_scenes/ come from dev/scenes/:

    • cube: Blender's default scene.
    • shape_cube: a cube of many faces with a Sphere shape key and a Twist modifier input.
    • arm: a Rigify left arm and hand.
    • mannequin: a whole Rigify figure without a face.

    The rigs are generated by Rigify, which ships with Blender, and the bodies are built around their bones; nothing comes from elsewhere.

  • Save it with the oldest Blender Kneady supports (4.2), so every supported Blender opens it. Use This File saves with the Blender that is running, and says so.

  • Its object, bone and region names are fixed: the steps' checks and starts name them.

  • Several tutorials can share one: put it in the tutorials folder's _scenes/ and give each "practice": "../_scenes/arm.blend". A practice path can reach a sibling folder of its tutorials folder, never past it. Copied to your folder to be edited, a tutorial takes its own copy of the scene along.

  • Keep it small; it ships with Kneady.

  • Use your own models. Anything from someone else needs its license checked and its attribution included.

Trying one

  • In the editor, Try This Step. Or set Help to Learn and pick it from Start a Tutorial, which opens its practice scene as a person would.
  • tests/test_tutorials.py checks every shipped tutorial reads without a problem, and that every path it checks, sets or lights is there in its practice scene.
  • tests/probe_tutorial.py plays the panel in a real window and clicks through it (see TESTING.md for running probes).
